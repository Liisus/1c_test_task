# Дневник обещаний

## Запуск

Через Docker Compose:

```bash
docker compose up --build
```

Открыть http://127.0.0.1:5000. При каждом старте контейнера выполняется
`python -m src.db.init_db`, затем запускается Flask. Если инициализация завершится
с ошибкой, сервер не запустится. Существующие записи при инициализации сохраняются.
SQLite хранится в именованном volume `diary_data`, смонтированном в `/app/instance`.
Остановка: `docker compose down`. Удаление контейнера не удаляет volume.

Исходники из корня репозитория копируются в контейнер в `/app`.
После изменения исходников повторить запуск с `--build`.

Без Docker (из корня репозитория):

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m src.db.init_db
flask --app src.app run
```

Открыть http://127.0.0.1:5000. Bootstrap скачан вручную и хранится в
`static/vendor/bootstrap/`. Приложение обслуживает статику локально.
JS bundle сохранён для будущих компонентов и пока не подключается к странице.

## Структура

```text
src/
  app/              # фабрика create_app и маршруты
  db/               # соединение SQLite, запросы, схема и инициализация
  models/           # фильтры и проверка входных данных
templates/          # Jinja2
static/             # CSS и локальный Bootstrap
instance/           # локальная база и настройки (не входят в Git)
```

`python -m src.db.init_db` создаёт недостающие таблицы без удаления данных. Это не система миграций.
База хранится в `instance/diary.sqlite3`. Необязательные локальные настройки
Flask можно задать в `instance/config.py`, например `DATABASE`.
Даты обещания и завершения предусмотрены в формате `YYYY-MM-DD`, время комментариев — UTC.

## Фильтры списка дел

`index` читает query-параметры и передаёт все найденные записи в `index.html`
как `cases`, а текущие фильтры — как объект `CaseFilters` в переменной `filters`.
Статический метод `CaseFilters.from_request(request)` читает и проверяет параметры.
Пустые фильтры представлены как `None`, даты — как строки `YYYY-MM-DD`.
Поисковая строка передаётся отдельно как `q`. Без параметров выводятся все дела.

- `q` — поиск подстроки в названии и описании; знаки препинания разрешены,
  `%`, `_`, обратный слеш и управляющие символы запрещены (HTTP 400).
- `status` — `open` или `closed`.
- `promised_from`, `promised_to` — включительные границы даты обещания (`YYYY-MM-DD`).
- `due_from`, `due_to` — включительные границы срока завершения (`YYYY-MM-DD`).

Например: `/?status=open&promised_from=2026-10-01&promised_to=2026-10-15&due_from=2026-10-16&due_to=2026-10-31`.
Фильтры применяются совместно. Неверный формат даты или статус возвращают HTTP 400.
Регулярное выражение проверяет формат даты, месяц 01–12 и день 01–31;
существование даты в календаре не проверяется.
Результат отсортирован по сроку завершения и идентификатору.

## Маршруты

GET-маршруты изменения данных (параметры передаются после `?`):

- `/cases/add?title=Новое&promised_on=2026-10-18&due_on=2026-10-31` — создать дело; `description` и `status` необязательны.
- `/cases/1/edit?title=Изменённое&status=closed` — изменить дело; непереданные поля сохраняются.
- `/cases/1/comments/add?body=Комментарий` — добавить комментарий к делу.
- `/comments/1/edit?body=Новый%20текст` — изменить текст комментария.

После сохранения выполняется перенаправление на список с якорем записи.
Несуществующий ID возвращает 404, некорректные параметры — 400.
Шаблон получает `cases` с ID дел; список комментариев находится в `case.comments`. У каждого комментария есть `id`, `case_id`, `body`, `created_at`.
